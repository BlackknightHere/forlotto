## 🔴 P0 — ต้องแก้ก่อนส่งให้ลุงใช้

### A. แท็บที่ถูกล็อก/conflict ยังกด Ctrl+Enter บันทึกโพยได้ → แจ้ง "บันทึกแล้ว" แต่ข้อมูลหาย
- **ยืนยันแล้ว (ทดสอบจริง):** เปิดแอป 2 แท็บ → แท็บเก่าขึ้น overlay "แอปถูกเปิดอยู่ในหน้าต่างอื่น" ถูกต้อง แต่ถ้าโฟกัสยังค้างอยู่ใน input ของฟอร์มโพย ผู้ใช้ยังพิมพ์ได้ กด Ctrl+Enter → toast "บันทึกแล้ว 1 รายการ" + ฟอร์มถูกล้าง แต่ `GET /api/db` ไม่มีรายการนั้น
- **สาเหตุ:**
  - `src/store.js` `update()` (~บรรทัด 138) `return` เงียบ ๆ เมื่อ `statusRef.current` เป็น `locked`/`conflict`
  - `src/pages/BuyPage.jsx` `submit()` เรียก `update(...)` แล้วถือว่าสำเร็จเสมอ → toast สำเร็จ + `setRows(blankRows())`
  - overlay `BlockingNotice` ใน `src/App.jsx` บังเมาส์ได้ แต่ไม่กันคีย์บอร์ด (ไม่มี focus trap / inert)
- **แก้ (ทำทั้งสองชั้น):**
  1. ให้ `update()` คืน `false` เมื่อไม่รับการแก้ไข (และ `true` เมื่อรับ) → ใน `BuyPage.submit()` ถ้าได้ `false` ให้ toast error เช่น "บันทึกไม่ได้ — แอปถูกเปิดอยู่ในหน้าต่างอื่น" และ **ไม่ล้างฟอร์ม** ; ไล่ดูจุดอื่นที่เรียก `update` แล้ว toast สำเร็จ (NumberModal แก้/ลบ, RecentEntries ลบ + เลิกทำ, LimitModal, EventsPage สร้าง/แก้/ลบงวด) ให้เช็กผลเช่นกัน — อาจทำ helper เล็ก ๆ กลาง
  2. เมื่อ status เป็น `locked`/`conflict`: เรียก `document.activeElement?.blur()` และใส่ attribute `inert` ที่ `.shell` (ส่วนที่อยู่ใต้ overlay) ให้ overlay เป็นส่วนเดียวที่โต้ตอบได้ และให้ปุ่มใน overlay ได้โฟกัส
- **เกณฑ์ผ่าน:** ทำซ้ำขั้นตอนทดสอบด้านบน → ฟอร์มไม่ถูกล้าง, ไม่มี toast สำเร็จ, พิมพ์ลงฟอร์มใต้ overlay ไม่ได้

## 🟡 P1/P2 — จุดย่อย

### B. `2-open-app.bat` บอก "จะปิดเองใน 5 วินาที" แต่ค้าง "Press any key"
- `server/index.js` (handler `server.on('error')` กรณี `EADDRINUSE`) `process.exit(0)` หลัง 5 วิ แต่ bat มี `pause` ต่อจาก `node ...` เสมอ
- **แก้:** ใน bat เปลี่ยน `pause` บรรทัดสุดท้ายเป็น `if errorlevel 1 pause` (ยังหยุดให้อ่านเมื่อ crash) — ไฟล์ `.bat` ต้องเป็น CRLF (`.gitattributes` บังคับไว้แล้ว)

### C. พอร์ต 5178 ไม่ว่าง → เดาว่าเป็นแอปตัวเองเสมอ
- ถ้าโปรแกรมอื่นใช้พอร์ตอยู่ จะเปิดเบราว์เซอร์ไปหน้าผิด
- **แก้:** ใน `EADDRINUSE` handler ลอง `fetch('http://127.0.0.1:PORT/api/db')` (Node 18+ มี fetch) ถ้าตอบ JSON ที่มี `version` → ถือว่าเป็นแอปเรา เปิดเบราว์เซอร์; ถ้าไม่ใช่ → แจ้งภาษาไทยว่าพอร์ตถูกโปรแกรมอื่นใช้ แนะนำตั้ง `LOTTO_PORT` แล้ว exit code 1 (bat จะ pause ให้อ่านหลังแก้ข้อ B)

### D. อัปเดตแอปแล้วลุงอาจยังเห็นหน้าเก่า
- `2-open-app.bat` build เฉพาะเมื่อไม่มี `dist\index.html`
- **แก้ (เลือกแบบง่ายที่สุด):** ให้ bat build ทุกครั้งที่ไฟล์ใน `src/` ใหม่กว่า `dist/index.html` — ทำใน Node script เล็ก ๆ (เช่น `server/needs-build.js` คืน exit code) ง่ายกว่าเขียนใน batch; หรืออย่างน้อยเพิ่มใน README ส่วน "อัปเดตเวอร์ชันใหม่" ว่าต้องรัน `1-install.bat` อีกครั้ง

### E. งวดที่จัดเก็บแล้ว ยังแก้ได้บางส่วน
- `BuyPage` บล็อกแล้ว แต่ใน `BoardPage` ยังตั้งยอดอั้น, แก้/ลบโพยใน `NumberModal`, กรอกเลขที่ออก/ตัวคูณใน `PayoutPanel` ได้ และ `RecentEntries` ยังลบได้ — ขัดกับแถบที่บอกว่า "ดูข้อมูลได้ แต่บันทึกโพยใหม่ไม่ได้"
- **ถามผู้ใช้ก่อน:** งวดที่จัดเก็บควร "อ่านอย่างเดียวทั้งหมด" หรือยังอนุญาตกรอกผลรางวัล/ตัวคูณ (เผื่อจัดเก็บก่อนหวยออก)? ถ้าผู้ใช้ไม่ตอบ ค่าเริ่มต้นที่แนะนำ: อ่านอย่างเดียวทั้งหมด + แถบเตือนเดียวกับ BuyPage ที่หน้า Board พร้อมปุ่ม "นำกลับมาใช้งาน"

### F. overlay ล็อกบอก "ข้อมูลในหน้านี้บันทึกไว้เรียบร้อยแล้ว" เสมอ
- `src/App.jsx` ข้อความของ `locked` ถูกต้องเฉพาะเมื่อ flush สุดท้ายสำเร็จ — ถ้า flush ล้มเหลว (status ภายในยัง retry อยู่) ข้อความนี้ผิด
- **แก้:** ใน `store.js` เก็บ flag ว่ายังมี `pending`/`inFlight` อยู่ไหม (expose เป็นค่าใน hook เช่น `hasUnsaved`) แล้วให้ overlay แสดง "กำลังบันทึกข้อมูลล่าสุด…" จนกว่าจะสำเร็จ หรือ "บันทึกข้อมูลล่าสุดไม่สำเร็จ" ถ้าล้มเหลว

### G. NumberModal: กดปุ่ม X ระหว่างแก้รายการ → ค่าที่แก้หาย
- `src/components/NumberModal.jsx` ส่ง `onDismiss` ให้ Esc/คลิกนอกกรอบแล้ว แต่ปุ่ม X ใน `Modal.jsx` เรียก `onClose` ตรง ๆ
- **แก้:** ให้ปุ่ม X ใน `Modal.jsx` เรียก `onDismiss` เช่นเดียวกัน (ตรวจว่า modal อื่นที่ส่ง `onDismiss` ยังทำงานถูก — `OverLimitModal` ใช้ `onClose={askCancel}` ไม่ได้ส่ง onDismiss จึงไม่กระทบ)

### H. เลือกเจ้าของ (ลุงแมว/ป้าจิก) ด้วยคีย์บอร์ดไม่ได้
- `BuyPage.jsx` ปุ่ม `Segmented` ของ owner ยัง `tabIndex={-1}`; บน/ล่างมีลูกศร ↑/↓ แล้ว
- **แนวทาง:** ใช้ ←/→ ในช่องหมายเหตุ หรือในทุกช่องของแถว (ระวังชนกับการเลื่อนเคอร์เซอร์ในช่องหมายเหตุ — ถ้าใช้ในช่องหมายเหตุ ให้ทำงานเฉพาะเมื่อช่องว่าง หรือใช้ Alt+←/→) และเพิ่มคำใบ้ใน `.kbd-hints` — **ถามผู้ใช้ก่อนว่าอยากได้ปุ่มไหน**
