# HANDOFF — แก้ไขตามผล QA (หวยลุงแมว)

> เอกสารนี้สำหรับส่งต่อให้ chat/agent ใหม่ไปแก้ไข อ่านให้จบก่อนเริ่มงาน
> ผล QA มาจากการอ่านโค้ดทุกไฟล์ (ยังไม่ได้ทดสอบการใช้งานในเบราว์เซอร์) — **ก่อนแก้แต่ละข้อ ให้เปิดไฟล์ตรวจว่ายังเป็นตามที่บอกจริง**

## บริบทโปรเจกต์

- แอปจดโพยหวยรัฐบาล (2 ตัวบน / 2 ตัวล่าง / 3 ตัวตรง-โต๊ด) ของ **ลุงแมว** (คนรับโพย) และ **ป้าจิก** (เจ้ามือ รับส่วนที่ลุงแมวตัดส่งเมื่อเกินอั้น) ใช้งานบนเครื่อง Windows เครื่องเดียว ผู้ใช้เป็นผู้สูงอายุ ไม่ใช่สายเทคนิค → ข้อความในแอปต้องเป็นภาษาไทย เข้าใจง่าย
- Stack: React 18 + Vite 6 (frontend), Express 4 (server) — JS ล้วน ไม่มี TypeScript, ไม่มีเทสต์, **ไม่ใช่ git repo**
- โครงสร้าง:
  - `server/index.js` — `GET/PUT /api/db` เก็บข้อมูลทั้งก้อนใน `data/db.json` มีเลข `version` กันเขียนทับ (optimistic lock → 409), สำรองวันละไฟล์ใน `data/backups/`
  - `src/store.js` — hook `useDb()` โหลด/บันทึกข้อมูลแบบ debounce 250ms
  - `src/lib.js` — logic คำนวณ (ยอดอั้น `getLimit`, `tabSummary` กำไร/ขาดทุน/ยอดจ่าย)
  - `src/pages/BuyPage.jsx` (คีย์โพย + ตัดส่งเมื่อเกินอั้น), `BoardPage.jsx` (ตารางยอดรวม), `EventsPage.jsx` (จัดการงวด)
  - `src/components/` — `Modal`, `Confirm`, `LimitModal`, `NumberModal`, `OverLimitModal`, `PayoutPanel`, `OwnerSelect`
- รัน dev: `npm run dev` (Vite 5173 + server 5178) — มี `.claude/launch.json` ชื่อ `dev` ใช้กับ preview_start ได้
- ผู้ใช้จริงรันผ่าน `1-install.bat` / `2-open-app.bat` (build ไป `dist/` แล้วเสิร์ฟจาก server ที่ 5178)

## ข้อห้าม / ข้อควรระวัง

- **ห้ามลบหรือเขียนทับ `data/`** (มีข้อมูลจริง) — ก่อนทดสอบให้ copy `data/db.json` สำรองไว้ หรือรันด้วยโฟลเดอร์ข้อมูลแยก
- รักษารูปแบบข้อมูลใน `db.json` ให้เข้ากันได้ย้อนหลัง ถ้าต้องเปลี่ยน schema (เช่น ข้อ 7) ต้องมี migration ตอนโหลด
- เขียนโค้ดตามสไตล์เดิม (ไม่มี semicolon, single quote, คอมเมนต์น้อย, ข้อความ UI ภาษาไทย)
- หลังแก้ ให้รัน `npm run build` ให้ผ่าน และทดสอบใน browser preview

## 🔴 P0 — ข้อมูลหาย/ซ้ำ (ทำก่อน)

### 1. เปิดหลายแท็บ → ข้อมูลหายเงียบ
- **ไฟล์:** `src/store.js` (ฟังก์ชัน `flush` ราว บรรทัด 30–56), `src/App.jsx` (แถบสถานะ บรรทัด ~101–109)
- **ปัญหา:** `pending.current = null` ก่อนส่ง → ถ้าได้ 409 ก็ `return` ทิ้ง body ไปเลย และ `version.current` ยังเก่า ทุกการแก้ต่อจากนั้นได้ 409 ตลอด ผู้ใช้คีย์ต่อได้แต่ไม่มีอะไรบันทึก มีแค่ข้อความเล็กมุมซ้ายล่าง และ `beforeunload` ไม่เตือนเพราะ pending เป็น null
- **ทริกเกอร์ง่าย:** ดับเบิลคลิก `2-open-app.bat` ทุกครั้งเปิดแท็บใหม่
- **แนวทางแก้ (แนะนำทำทั้งสองอย่าง):**
  1. ตอน 409 ให้เก็บ body คืน (`pending.current ??= body`) และแสดง overlay เต็มจอ (บล็อกการคีย์) บอกว่า "แอปถูกเปิดอยู่ในหน้าต่างอื่น" พร้อมปุ่มโหลดใหม่ — ระวัง: ถ้าโหลดใหม่ ข้อมูลที่ค้างจะหาย ต้องบอกผู้ใช้ชัด ๆ
  2. ป้องกันตั้งแต่ต้นด้วย `BroadcastChannel` / `navigator.locks`: ให้แท็บใหม่แจ้งแท็บเก่า แล้วแท็บใดแท็บหนึ่งเข้าโหมด "ใช้งานในหน้าต่างอื่นอยู่" (ล็อก UI)
- **เกณฑ์ผ่าน:** เปิด 2 แท็บ คีย์ในแท็บใดแท็บหนึ่ง → ไม่มีกรณีที่ผู้ใช้คีย์ได้แต่ข้อมูลไม่ถูกบันทึกโดยไม่มีการเตือนเด่นชัด

### 2. Server บันทึกไฟล์ล้มเหลว → version เพี้ยน
- **ไฟล์:** `server/index.js` handler `app.put('/api/db')` (~บรรทัด 63–75)
- **ปัญหา:** `state = {...}` ถูก assign ก่อน `save()` สำเร็จ ถ้า save throw → ตอบ 500 แต่ state ในหน่วยความจำเลื่อน version ไปแล้ว → ครั้งต่อไปไคลเอนต์ได้ 409 → ตกข้อ 1
- **แก้:** สร้าง `next` ก่อน, `save(next)`, สำเร็จแล้วค่อย `state = next`
- **เกณฑ์ผ่าน:** จำลองให้ `save` throw ครั้งเดียว แล้วครั้งต่อไปบันทึกได้ปกติ (ไม่ 409)

### 3. กดยืนยันซ้ำ → โพยซ้ำ / ค้าง
- **ไฟล์:** `src/pages/BuyPage.jsx` `submit()` (~บรรทัด 264)
- **ปัญหา:** ไม่มีกันกดซ้ำ คลิกปุ่มหรือ Ctrl+Enter สองครั้งเร็ว ๆ → บันทึก 2 ชุด; ถ้ากดซ้ำตอน OverLimitModal เปิด → `setOverLimit` ถูกทับ promise แรกค้างตลอด
- **แก้:** ใช้ `useRef` flag `submitting` (ไม่ใช่ state อย่างเดียว เพราะต้องกันใน tick เดียวกัน) เช็กต้นฟังก์ชัน และ reset ใน `finally`; ปุ่ม disabled ระหว่าง submit
- **เกณฑ์ผ่าน:** ดับเบิลคลิก/กด Ctrl+Enter รัว ๆ → บันทึกครั้งเดียว

### 4. แถวมีเงินแต่ไม่มีเลข → ถูกทิ้งเงียบ
- **ไฟล์:** `src/pages/BuyPage.jsx` `validate()` (`if (!r.number) continue` ~บรรทัด 243)
- **แก้:** ถ้า `!r.number` แต่มี `amount`/`straight`/`tod` (หรือ note) → `errs[r.id] = 'ยังไม่ได้ใส่เลข'` ; แถวว่างทั้งแถวยังข้ามได้ตามเดิม
- **เกณฑ์ผ่าน:** แถวที่มีแต่หมายเหตุ/เงิน ขึ้น error ไม่บันทึกทั้งใบ

## 🟠 P1 — คำนวณผิด / ใช้งานติดขัด

### 5. Validate ตัวเลขไม่ครบ
- `src/components/LimitModal.jsx` ช่อง "ทุกเลขเท่ากัน" (`all`): พิมพ์ `1.2.3` ได้ → `Number()` = NaN → JSON เป็น `null` = ไม่อั้นเงียบ ๆ → เพิ่มเข้าเงื่อนไข `valid` (ต้องเป็นตัวเลขจริง ≥ 0) และแสดง error
- `src/pages/EventsPage.jsx` ส่วนลด `meaw`/`jik`: ค่าเพี้ยนกลายเป็น 0 และใส่ >100 ได้ → validate 0–100 ปิดปุ่มบันทึกถ้าไม่ถูก
- พิจารณาทำ helper กลางใน `lib.js` สำหรับ sanitize เงิน (อนุญาตจุดได้ตัวเดียว) แล้วใช้แทน `replace(/[^\d.]/g, '')` ที่กระจายอยู่หลายไฟล์

### 6. เลือก "ล่าง" / เจ้าของ ด้วยคีย์บอร์ดไม่ได้
- `src/pages/BuyPage.jsx` `Segmented` ตั้ง `tabIndex={-1}` ทำให้คีย์ด้วย Enter ล้วนไม่ได้สำหรับ 2 ตัวล่าง
- **แนวทาง:** เพิ่มปุ่มลัดตอน focus อยู่ในแถว เช่น ในช่องเลข/เงิน กด `+` = บน, `-` = ล่าง (หรือ ↑/↓) และแสดงคำใบ้ใน `.kbd-hints` — **ถามผู้ใช้ก่อนว่าอยากได้ปุ่มไหน** ถ้าไม่แน่ใจ ใช้ `+`/`-`
- ถ้าเพิ่มปุ่มลัด ต้องไม่ให้ตัวอักษรนั้นไปโผล่ในช่อง input (preventDefault)

### 7. เลขที่ออกต้องกรอกซ้ำ 6 ช่อง
- `src/components/PayoutPanel.jsx` + `lib.js` (`emptyPayouts`, `tabSummary`)
- ตอนนี้ `event.payouts[owner][type].number` แยกตามเจ้าของ แต่หวยรัฐบาลออกเลขเดียวกัน
- **แนวทาง:** ย้ายเลขที่ออกไปที่ `event.results = { top, bottom, three }` เก็บแค่ตัวคูณใน `payouts[owner][type]`; ตอนโหลด (ใน `useDb` หรือ util migrate) ถ้ายังไม่มี `results` ให้ดึงจาก payouts ของ `meaw` ก่อน ถ้าว่างใช้ของ `jik`
- `tabSummary` ต้องอ่านเลขจาก `event.results`

### 8. ไม่บอกว่าใครถูกรางวัล
- เพิ่มส่วน "รายการที่ถูกรางวัล" (ใน `PayoutPanel` หรือการ์ดใหม่ใน BoardPage) แสดง: หมายเหตุ(ชื่อคนซื้อ), เลข, ประเภท, ยอดซื้อ, ยอดจ่าย ต่อรายการ (entry) ของเจ้าของที่เลือก
- ทำ logic เป็นฟังก์ชันใน `lib.js` (เช่น `winningEntries(event, entries, owner)`) เพื่อให้เทสต์ได้; 3 ตัวต้องแยกจ่ายตรง/โต๊ดต่อรายการ

### 9. Esc / คลิกนอกกรอบ ทิ้งงานที่ยังไม่บันทึก
- `NumberModal`: ถ้า `editing` อยู่ Esc ควรยกเลิกการแก้ (ออกจากโหมดแก้) แทนปิด modal
- `OverLimitModal`: Esc/คลิก backdrop = "ยกเลิกทั้งใบ" → ควรถามยืนยันด้วย `useConfirm()` ก่อน
- `Modal.jsx` อาจเพิ่ม prop เช่น `onEscape` หรือ `confirmClose`

### 10. งวดที่จัดเก็บแล้วยังคีย์โพยได้
- `App.jsx` / `BuyPage.jsx`: ถ้า `event.archived` → หน้า BuyPage แสดงแถบเตือนเด่น ๆ "งวดนี้จัดเก็บแล้ว" และปิดการบันทึก (หรือมีปุ่ม "นำกลับมาใช้งาน")

## 🟡 P2 — ปรับปรุงเล็กน้อย

11. `1-install.bat`: `where node >/dev/null 2>nul` → เปลี่ยนเป็น `where node >nul 2>nul` (ทดสอบแล้ว ของเดิมพ่น "The system cannot find the path specified." ภาษาอังกฤษ)
12. `server/index.js`: ถ้า `listen` เจอ `EADDRINUSE` (แอปเปิดอยู่แล้ว) → แค่เปิดเบราว์เซอร์ไปที่ URL เดิมแล้ว exit พร้อมข้อความไทย แทนการ crash
13. `server/index.js` `backupToday()`: ใช้วันที่ตามเวลาเครื่อง (ไม่ใช่ `toISOString()` ที่เป็น UTC); พิจารณาสำรองก่อนการลบงวด (ทำฝั่ง server ไม่ได้รู้ว่าเป็นการลบ — อาจทำ backup ทุก N ชั่วโมงแทน)
14. `src/store.js`: retry ตอน error ทุก 250ms ไม่สิ้นสุด → ใส่ backoff (เช่น 1s, 2s, 5s, สูงสุด 10s) และใน `App.jsx` ทำแถบแดงเด่นเมื่อ status เป็น `error`/`conflict`
15. `PayoutPanel.jsx` ตัวคูณ: ค่าว่างถูกเก็บเป็น `0` ทำให้พิมพ์ได้ "09" และชนิดปน string/number → เก็บเป็น string ที่ผู้ใช้พิมพ์ (ว่างได้) แล้วแปลงเป็นเลขตอนคำนวณเท่านั้น
16. `BuyPage.jsx` `onKeyDown`: Enter ที่ช่องสุดท้าย ให้เพิ่มแถวเฉพาะเมื่อแถวสุดท้ายมีเลขแล้ว
17. 3 ตัวโต๊ด: ตัวคูณเดียวทุกเลข แต่เลขตัวซ้ำ (เช่น 112 = 3 กลับ) เจ้ามือบางเจ้าจ่ายต่างจาก 6 กลับ → **ถามผู้ใช้ก่อน** ว่าต้องแยกไหม ห้ามเดาเอง
